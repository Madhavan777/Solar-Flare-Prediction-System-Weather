## 3. Open item 1 resolved: the consecutive-window gap figure

The report states that 97.9 % of consecutive same-active-region windows are one hour apart. That
figure **does not reproduce under any definition I could construct.** The correct value is
**98.60 %**.

Grouping the 331,185 windows by `ar`, sorting by observation-window start and differencing gives
exactly **327,980 gaps** (331,185 windows − 3,205 active regions), of which **323,377 are exactly
1.00 h**:

| Definition | Groups | Gaps | Exactly 1.00 h |
|---|---|---|---|
| A — by `ar`, ordered by window **start** | 3,205 | 327,980 | **98.5966 %** |
| B — by `ar`, ordered by window **end** | 3,205 | 327,980 | 98.5966 % |
| C — by (`partition`, `ar`), ordered by start | 3,205 | 327,980 | 98.5966 % |
| D — by (`ar`, `folder`), ordered by start | 3,360 | 327,825 | 98.5398 % |
| E — as A, de-duplicated on (`ar`, `start`) | 3,205 | 327,980 | 98.5966 % |

The statistic is stable at 98.54–98.60 % across all five readings; 97.9 % would require 321,092
one-hour gaps, 2,285 fewer than are present. Definitions A, B, C and E coincide because no active
region crosses a partition and there are **no duplicate (`ar`, `start`) pairs and no duplicate file
names** in the metadata.

Supporting detail: the minimum gap is **1.00 h** (so windows never repeat or run backwards), the
maximum is **171.00 h**, and the median is 1.00 h. The non-one-hour gaps cluster at 12–16 h
(15 h: 748, 14 h: 534, 13 h: 457, 16 h: 333, 12 h: 331), i.e. observation outages rather than
irregular sampling. Only 0.04 pp of gaps fall between 1 h and 2 h.

**Why this matters for the leakage argument:** a 1 h step between consecutive 12 h windows means
adjacent windows of the same active region share 11 of their 12 hours of data. With 98.6 % of
transitions at that 1 h step, a random train/test split would place near-duplicate windows on both
sides of the split. This is the quantitative justification for the chronological partition split.

**Recommendation:** the report's 97.9 % should read 98.6 %. The report is frozen and was not edited;
this is the owner's call. The definition above is recorded in
[DATA_CARD.md](DATA_CARD.md) so that whichever number is published can be traced.
